# Техническое задание: сайт «Японика Сочи»

## 1. Общее описание

Интернет-каталог азиатской косметики и товаров для дома «Японика Сочи» с личными кабинетами, персональными скидками, корзиной и заказом без онлайн-оплаты.

**Основные функции:**
- Каталог товаров с ценами, поиском, фильтрами и сортировкой
- Корзина с сохранением между визитами
- Оформление заказа без оплаты (заказ отправляется продавцу по email)
- Авторизация по номеру телефона с паролем
- Персональные скидки для каждого пользователя
- Акции двух типов: на группы товаров и «оранжевые ценники»
- Импорт каталога и скидок из 1С в формате JSON
- Админ-панель для управления товарами, пользователями и заказами
- Журнал обменов данных

**Целевая аудитория:** покупатели магазина «Японика Сочи», в том числе те, кто уже покупал офлайн.

**Язык:** русский. **Валюта:** рубли (₽).

## 2. Роли пользователей

### 2.1. Гость (не авторизован)
- Просматривает каталог с обычными ценами
- Видит акционные цены
- Может собирать корзину
- При оформлении заказа указывает телефон и придумывает пароль (минимум 4 символа)
- Если телефон есть в базе (покупал ранее) — применяется его персональная скидка

### 2.2. Авторизованный пользователь
- Видит обе цены: обычную и свою (со скидкой)
- Видит размер своей скидки в личном кабинете
- Корзина сохраняется между визитами
- История заказов
- Кнопка «Повторить заказ»

### 2.3. Администратор
- Управляет товарами (CRUD)
- Загружает изображения к товарам
- Управляет пользователями (назначение скидок, сброс пароля)
- Управляет заказами (смена статуса)
- Запускает импорт данных вручную
- Видит журнал обменов
- Видит опцию «не применять скидки» у товара

## 3. Структура страниц

### 3.1. Главная страница

- Популярные товары или новинки

### 3.3. Карточка товара

- Артикул
- Изображения (галерея, загружается админом)

- Ключевые компоненты
- Наличие: «в наличии» / «под заказ»

### 3.4. Корзина
- Список товаров с количеством
- Цены (обычная и со скидкой для авторизованного)
- Товары «под заказ» помечены отдельно
- Поле «Комментарий к заказу» (подставляется из предыдущего заказа)
- Кнопка «Оформить заказ»

### 3.5. Оформление заказа (для гостя)
- Телефон
- Пароль (минимум 4 символа)
- Подтверждение пароля
- Комментарий к заказу

### 3.6. Личный кабинет
- Имя (можно редактировать)
- Телефон
- Размер скидки
- История заказов
- Кнопка «Повторить заказ» у каждого заказа
- Выход

### 3.7. Страницы
- «О нас»
- «Контакты» (адреса, телефоны, ссылки на карты Yandex и 2GIS, расписание)

## 4. Схема данных

### 4.1. Товар (Product)
```
id: integer, PK
article: string, уникальный (артикул)
name: string (название)
description: text (описание)
price: decimal (обычная цена)
quantity: integer (остаток)
no_discount: boolean (не применять скидки)
created_at: datetime
updated_at: datetime
```

### 4.2. Изображение товара (ProductImage)
```
id: integer, PK
product_id: integer, FK → Product
file_path: string (путь к файлу)
sort_order: integer (порядок сортировки)
```

### 4.3. Категория (Category)
```
id: integer, PK
name: string (название)
slug: string (для URL)
parent_id: integer, FK → Category, nullable (для подкатегорий)
```

### 4.4. Связь товар-категория (ProductCategory)
```
product_id: integer, FK → Product
category_id: integer, FK → Category
```

### 4.5. Ключевой компонент (Component)
```
id: integer, PK
name: string (название, например «муцин улитки»)
```

### 4.6. Связь товар-компонент (ProductComponent)
```
product_id: integer, FK → Product
component_id: integer, FK → Component
```

### 4.7. Акция (Promo)
```
id: integer, PK
name: string (название акции, например «Уход за лицом −15%»)
discount: integer (процент скидки)
start_date: datetime (начало)
end_date: datetime (конец)
```

### 4.8. Связь товар-акция (ProductPromo)
```
product_id: integer, FK → Product
promo_id: integer, FK → Promo
```

### 4.9. Пользователь (User)
```
id: integer, PK
phone: string, уникальный (логин)
name: string (имя)
password_hash: string (хеш пароля)
discount: integer (персональная скидка, 0–40%)
discount_end_date: datetime, nullable (окончание действия скидки)
is_admin: boolean (права администратора)
created_at: datetime
updated_at: datetime
```

### 4.10. Заказ (Order)
```
id: integer, PK
user_id: integer, FK → User
phone: string (телефон на момент заказа)
name: string (имя на момент заказа)
comment: text (комментарий к заказу)
status: enum (Отправлен, Согласован, Закрыт)
total_retail: decimal (сумма по розничным ценам)
total_final: decimal (итоговая сумма со скидками)
created_at: datetime
```

### 4.11. Позиция заказа (OrderItem)
```
id: integer, PK
order_id: integer, FK → Order
product_id: integer, FK → Product
product_name: string (название на момент заказа)
product_article: string (артикул на момент заказа)
price_retail: decimal (розничная цена на момент заказа)
price_final: decimal (цена со скидкой на момент заказа)
quantity: integer
is_preorder: boolean (под заказ)
notify_on_available: boolean (связаться при появлении)
```

### 4.12. Корзина (Cart)
```
id: integer, PK
user_id: integer, FK → User, nullable (для гостей — session_id)
session_id: string, nullable (для гостей)
created_at: datetime
updated_at: datetime
```

### 4.13. Позиция корзины (CartItem)
```
id: integer, PK
cart_id: integer, FK → Cart
product_id: integer, FK → Product
quantity: integer
notify_on_available: boolean (связаться при появлении)
```

### 4.14. Журнал обменов (ExchangeLog)
```
id: integer, PK
operation: string (тип: «Импорт товаров», «Передача заказа» и т.д.)
result: string (Ok, Error)
message: text, nullable (детали ошибки)
created_at: datetime
```

## 5. Бизнес-логика

### 5.1. Расчёт цены
1. Берётся обычная цена товара
2. Если у товара `no_discount = true` — цена не меняется
3. Иначе определяется максимальная скидка:
   - Персональная скидка пользователя (если авторизован и скидка активна)
   - Скидки по акциям (если товар участвует в активных акциях)
4. Применяется большая из двух скидок (не суммируются)
5. Округление до рублей в меньшую сторону

### 5.2. Акции
- **Акция на группу товаров**: объявляется раз в неделю, действует с пятницы по понедельник. Товары привязываются к категориям.
- **«Оранжевые ценники»**: на конкретные товары, процент скидки выше обычных акций. Список задаётся вручную.
- Один товар может участвовать в обеих акциях.
- Бейджик «Акция -X%» показывается в каталоге и карточке товара.

### 5.3. Импорт из 1С
- Формат: JSON
- Источники: ручная загрузка файлом / забор по FTP с заранее оговорённого адреса
- **Товары**: обновляются по артикулу. Если товара нет в новом пакете — остаток обнуляется, статус «под заказ».
- **Пользователи**: обновляются по телефону. Новые создаются. Поле `name` не перезаписывается (пользователь сам себя назвал на сайте).
- **Скидки**: обновляются с учётом `discount_end_date`.
- Журнал обменов фиксирует каждую операцию.

### 5.4. Формат JSON для импорта

```json
{
  "products": [
    {
      "article": "AB-123",
      "name": "Пенка с муцином улитки",
      "description": "Описание товара...",
      "price": 1450,
      "quantity": 12,
      "no_discount": false,
      "categories": ["Уход за лицом", "Очищение"],
      "components": ["муцин улитки", "гиалуроновая кислота"],
      "promos": [
        {
          "name": "Уход за лицом −15%",
          "discount": 15
        },
        {
          "name": "Оранжевый ценник",
          "discount": 25
        }
      ]
    }
  ],
  "users": [
    {
      "phone": "+79123456789",
      "discount": 15,
      "discount_end_date": "2025-12-31T23:59:59"
    }
  ]
}
```

### 5.5. Оформление заказа

1. Пользователь (гость или авторизованный) заполняет корзину
2. При оформлении гость указывает:
   - Телефон
   - Имя
   - Пароль (минимум 4 символа)
   - Подтверждение пароля
3. Если телефон есть в базе (покупал ранее):
   - Если имя и пароль пустые — пользователь заполняет их
   - Применяется персональная скидка
4. Если телефона нет — создаётся новый пользователь с скидкой 0%
5. Заказ сохраняется со статусом «Отправлен»
6. Письмо с заказом отправляется на email продавца
7. Корзина очищается

### 5.5.1. Товары «под заказ» в корзине

- Товары с остатком 0 отображаются «серыми»
- Для таких товаров доступны две опции:
  - **«Предложить замену»** — покупатель хочет альтернативу
  - **«Сообщить, когда появится»** — покупатель ждёт этот товар
- Выбор покупателя сохраняется в корзине и передаётся в заказ
- Продавец видит выбор покупателя в письме с заказом

### 5.6. Статусы заказа
- **Отправлен** — заказ оформлен, письмо ушло продавцу
- **Согласован** — продавец связался с покупателем, всё уточнил
- **Закрыт** — заказ выполнен или отменён

Смена статуса — вручную администратором.

### 5.7. Повтор заказа
- Нажимает «Повторить заказ»
- Корзина наполняется товарами и количеством из старого заказа
- Цены пересчитываются по текущим данным (скидки, акции)
- Товары, которых нет в наличии, помечаются «под заказ»

### 5.8. Восстановление пароля
1. Пользователь нажимает «Забыл пароль»
2. Указывает телефон
3. Письмо отправляется администратору
4. Администратор вручную сбрасывает пароль
5. Пользователь может делать заказы по розничным ценам, пока пароль не восстановлен

## 7. Технические требования

### 7.1. Хостинг
- Shared-хостинг (поддержка PHP и MySQL)

### 7.2. База данных
- MySQL или MariaDB

### 7.3. Почта
- Отправка через SMTP (mail.ru или другой почтовый сервис)
- Email продавца: указывается в настройках

### 7.4. Производительность
- Каталог на 1000+ товаров
- Пагинация по 20–50 товаров
- Индексы по: артикул, название, категория, компоненты

### 7.5. Безопасность
- Пароли хранятся в виде хеша
- Защита от SQL-инъекций (подготовленные запросы)
- Защита от XSS (экранирование вывода)
- CSRF-токены для форм
- HTTPS

### 7.6. Адаптивность
- Мобильная версия (основной трафик — с телефонов)
- Desktop-версия
